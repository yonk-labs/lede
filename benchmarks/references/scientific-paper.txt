The paper investigates floating-point divergence between CPython 3.12 and Rust stdlib numerical code in deterministic text-processing pipelines. CPython 3.12 adopted Neumaier compensated summation for its built-in sum function, but the Rust standard library's Iterator::sum still uses naive left-fold, producing one to three ULP differences on TF-IDF score accumulations of six or more terms. Evaluation on a 5,000-document corpus found 241 documents whose Rust outputs diverged from Python by at least one byte, always traceable to ULP-level score differences changing stable-sort order; aggregate absolute error stayed under 4.8e-14. Porting CPython's Neumaier summation to Rust (a 12-line safe implementation with no measurable release-build overhead) restored bit-identical output across all 5,000 documents. Recommendation: Rust code aiming for byte-identical output to CPython 3.12+ should audit floating-point accumulation paths and adopt Neumaier summation where sums of six or more terms occur.
