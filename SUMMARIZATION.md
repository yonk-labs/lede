# Summarization Workflow

> How TaskStash generates summaries, step by step.

---

## Overview

TaskStash summarizes content at two levels:

1. **Structural summaries** (JSON/SQL): Schema-preserving summaries with column names, row counts, and sample data. These are generated by `ContentAwareMiddleware` and are specific to structured data.

2. **Text summaries**: Extractive sentence selection via TF-IDF scoring. This is the default for all text content and all preview/summary paths across the codebase.

LLM-based summarization is available as an opt-in upgrade for use cases requiring abstractive summarization (rephrasing, condensing, answering questions about the content).

---

## The Summarization Decision Tree

```
Content arrives at summarization point
         │
         ▼
  Is it structured data (JSON array / SQL table)?
         │
    ┌────┴────┐
    │Yes      │No
    ▼         ▼
  Schema-   Text content
  preserving  │
  summary     ▼
  (sample   Is an LLM provider configured
  rows +     AND method == "auto" or "llm"?
  columns)    │
              ├── Yes ──▶ LLM summarization (abstractive)
              │
              ├── No, method == "extractive" or "auto" (no LLM)
              │          ──▶ Extractive summarization (sentence selection)
              │
              └── method == "truncate"
                         ──▶ Character truncation (content[:N]+"...")
```

## Step-by-Step: Extractive Summarization Pipeline

When `smart_summarize(text, max_length)` is called:

### Step 1: Short-circuit checks

```
Input text ≤ max_length?  →  Return text unchanged
max_length < 50 chars?    →  Fall back to truncation (too short for sentences)
```

### Step 2: Sentence splitting

The text is split into sentences using regex heuristics:
- Splits on `.!?` followed by whitespace and an uppercase letter
- Handles abbreviations (Mr., Dr., U.S., etc.) — these don't trigger a split
- Handles decimal numbers (3.14 is not a sentence boundary)
- Splits on paragraph breaks (double newlines)

```
Input: "Dr. Smith analyzed the Q4 results. Revenue grew 23%.
        The Enterprise segment led growth. Churn remained flat."

Output: ["Dr. Smith analyzed the Q4 results.",
         "Revenue grew 23%.",
         "The Enterprise segment led growth.",
         "Churn remained flat."]
```

If fewer than 3 sentences are found, falls back to truncation.

### Step 3: Score each sentence

Three scoring dimensions, weighted:

| Dimension | Weight | What it measures |
|-----------|--------|------------------|
| **TF-IDF** | 60% | Term importance — sentences with rare, distinctive words score higher |
| **Position** | 25% | Lead/tail bias — first and last sentences score highest |
| **Length** | 15% | Sweet spot — 10-30 word sentences score highest |

Each dimension produces scores normalized to [0, 1]. The composite score is:

```
score = 0.60 × tfidf + 0.25 × position + 0.15 × length
```

**Optional upgrade**: If `nltk` is installed, TextRank (graph-based PageRank over sentence similarity) replaces the TF-IDF component. TextRank captures inter-sentence relationships and produces better results on long, complex documents.

### Step 4: Greedy selection

Sentences are sorted by composite score (highest first). They are greedily added to the output until the character budget (`max_length`) is exhausted:

```
Budget: 200 chars remaining
Candidate: "The Enterprise segment led growth." (35 chars) → fits, add it
Candidate: "Revenue grew 23%." (18 chars) → fits, add it
Candidate: "Dr. Smith analyzed the Q4 results." (34 chars) → fits, add it
Candidate: "Churn remained flat." (20 chars) → fits, add it
```

### Step 5: Reorder by original position

Selected sentences are reordered to match their original position in the text. This ensures the output reads naturally:

```
Output: "Dr. Smith analyzed the Q4 results. Revenue grew 23%.
         The Enterprise segment led growth. Churn remained flat."
```

### Step 6: Fallback

If the greedy selection produces an empty result (all sentences are individually longer than the budget), falls back to character truncation.

## Where Summarization Happens

Every path through TaskStash that generates a preview or summary uses `smart_summarize()`:

### Middleware Layer (Hot Path — Extractive Only)

| Component | When | What |
|-----------|------|------|
| `TaskStashMiddleware` | Text output > threshold | Generates preview in replacement message |
| `ContentAwareMiddleware._intercept_text()` | Text content intercepted | Generates preview for text documents |

These are on the critical path between tool output and LLM input. They use `smart_summarize()` directly (synchronous, sub-millisecond) — async LLM calls would add unacceptable latency.

### LangChain Tools (Advisory — Extractive Default)

| Tool | When | What |
|------|------|------|
| `StashQueryTool` | Query results returned | Preview of each matching artifact |
| `StashSummarizeTool` | Agent requests summary | Extractive summary of artifact content |

### Langflow Components (Configurable — Auto/LLM/Extractive/Truncate)

| Component | When | What |
|-----------|------|------|
| `StashSummarize` | User requests summary | **Configurable**: auto, llm, extractive, or truncate |
| `StashInvisible` | Content auto-intercepted | Preview in invisible mode output |
| `TaskStashAgent` | Tool output intercepted | Preview in agent's internal flow |
| `StashQuery` | Search results displayed | Preview of matching chunks/artifacts |

### MCP Tools (Extractive Only)

| Tool | When | What |
|------|------|------|
| `taskstash_query` | Query results returned | Preview of each matching artifact |
| `taskstash_summarize` | Client requests summary | Extractive summary of artifact content |

### Invisible Mode Interceptor

| Component | When | What |
|-----------|------|------|
| `ContentInterceptor` | Content intercepted by rules | Summary for replacement message |

## Switching to LLM Summarization

Extractive summarization is the default. To use LLM-based summarization:

### Option 1: Configuration File (Global)

In `.taskstash.yaml`:

```yaml
summarization:
  provider: openai         # or ollama, transformers, llama-cpp, external
  model: gpt-4o-mini       # model-specific
  api_key: sk-...          # or set TASKSTASH_OPENAI_API_KEY env var
```

This configures a `SummarizationProvider` that the Langflow `StashSummarize` component's `auto` mode will use when available.

### Option 2: Langflow Component (Per-Component)

The `StashSummarize` component has a **Method** dropdown:

| Method | Behavior |
|--------|----------|
| `auto` | Use LLM if a provider is configured in TaskStash Memory, else extractive |
| `llm` | Require LLM provider (error if none configured) |
| `extractive` | Always use extractive sentence selection |
| `truncate` | Always use character truncation (`content[:N]+"..."`) |

To use LLM summarization in Langflow:
1. Configure a summarization provider in the `TaskStash Memory` component
2. Set the `StashSummarize` method to `auto` or `llm`

### Option 3: Provider Factory (Programmatic)

```python
from yonk_taskstash.core.config import SummarizationConfig
from yonk_taskstash.summarization.factory import get_summarization_provider

# Extractive (zero dependencies)
config = SummarizationConfig(provider="extractive")
provider = get_summarization_provider(config)
summary = await provider.summarize(text, max_length=500)

# OpenAI (requires API key)
config = SummarizationConfig(provider="openai", model="gpt-4o-mini", api_key="sk-...")
provider = get_summarization_provider(config)
summary = await provider.summarize(text, max_length=500)
```

### What LLM Summarization Does NOT Affect

The middleware and MCP layers always use extractive summarization for previews, even when an LLM provider is configured. This is by design:

- **Middleware** (`TaskStashMiddleware`, `ContentAwareMiddleware`): Operates on the hot path between tool output and LLM. Adding an async LLM call here would block the agent pipeline.
- **MCP tools** (`taskstash_query`, `taskstash_summarize`): Previews use extractive. The LLM client can always call `taskstash_fetch` for full content.

LLM summarization is available through:
- Langflow `StashSummarize` component (explicit user control)
- `SummarizationProvider` API (programmatic access)
- `SummarizationConfig` with `provider: "openai"` etc.

## Performance Characteristics

| Text Size | Extractive Latency | LLM Latency (OpenAI) |
|-----------|-------------------|---------------------|
| 1 KB | < 1ms | 500-1000ms |
| 10 KB | < 5ms | 1000-2000ms |
| 100 KB | < 50ms | 2000-5000ms |

Extractive summarization is **deterministic** — the same input always produces the same output. LLM summarization varies between calls.

## Available Summarization Providers

| Provider | Config Value | Dependencies | Use Case |
|----------|-------------|--------------|----------|
| Extractive | `extractive` | None | Default, fast, deterministic |
| OpenAI | `openai` | `openai` package | Highest quality abstractive summaries |
| Ollama | `ollama` | Ollama server running | Local LLM, no API costs |
| Transformers | `transformers` | `transformers`, `torch` | Local neural summarization (BART) |
| llama-cpp | `llama-cpp` | `llama-cpp-python` | Efficient local GGUF models |
| External | `external` | Custom API endpoint | Custom summarization service |
| None | `none` | - | Disable provider (extractive still used via `smart_summarize`) |

**Important**: Setting `provider: "none"` does NOT disable summarization. It disables the `SummarizationProvider` interface. Extractive summarization via `smart_summarize()` is always available and always used for middleware/MCP previews regardless of this setting.
