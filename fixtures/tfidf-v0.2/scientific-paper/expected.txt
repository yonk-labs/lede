We investigate the sources of floating-point divergence between CPython 3.12 and Rust stdlib numerical code in the context of deterministic text processing pipelines. We recommend that any numerical Rust code intended to produce output byte-identical to CPython 3.12+ adopt Neumaier summation where floating-point sums of six or more terms occur. The root cause of observed divergence was the CPython 3.12 switch to compensated summation, which the Rust standard library does not match.
